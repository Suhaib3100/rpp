## 1. Summary of what was built and measured

SAGE-HE reaches **100.00%** test accuracy (macro F1 100.00%) against
**93.98%** (macro F1 93.98%) for a faithful reproduction of the
Jia et al. (2023) baseline, over 3 independent seeds on one identical
held-out test split of 360 images.

Four findings are worth stating up front because they shape
how everything else should be read:

1. **We could not reproduce the published 97.1%.** Implementing the base
   paper as described yields 93.98%. The paper
   under-specifies its architecture and reports no evaluation protocol, so the gap
   cannot be attributed with confidence — but it is reported rather than elided.
2. **NEU-CLS is saturated.** A pretrained EfficientNet-B0 reaches 100% test accuracy
   within two epochs. At full training size no architectural comparison on this
   dataset is informative, so component contributions are measured in a reduced-data
   regime and the full-data numbers are reported as a ceiling.
3. **Encryption costs latency, not accuracy.** Encrypted and plaintext inference
   agree on 100.00% of test images
   (0 flips of 360), with maximum absolute
   logit error 1.43e-02.
4. **The proposed architectural components do not help.** Measured against its own
   EfficientNet-B0 backbone under matched seeds and matched data, the full model
   scores lower on every seed, and so does the variant that adds the multi-scale
   local branch. (The finer attribution between chunk attention and the Sobel
   prior does not separate cleanly at this sample size and is not claimed — see
   §6.3.) This is a negative result for the architecture proposed in §3,
   and §6.3 reports it in full rather than burying it. The parts of the project
   that do hold up — the reproduction and audit, the encrypted inference, the
   evaluation methodology — are unaffected, and it was that methodology which
   made the negative result visible instead of hiding it behind a saturated 100%.

## 2. Dataset and integrity audit

NEU-CLS: 1800 images, 6 classes,
300 per class (True), all [200, 200] grayscale —
matching the published specification of the database.

### 2.1 Exact duplicates

SHA-256 hashing over raw pixels found **1 duplicate pair**. Both copies carry
the same label and both sit in the mirror's training split, so the duplication is
benign in the source — but merging and re-splitting could place the two copies on
opposite sides of the train/test boundary. The splitter therefore deduplicates
before splitting, leaving 1799 unique images.

### 2.2 Near-duplicate / leakage audit

NEU-CLS patches are cropped from a smaller set of source strip photographs, so
pixel-identical deduplication alone does not rule out leakage. Cosine similarity
between every test and training image, at several resolutions, with a high-pass
control that removes low-frequency illumination:

| representation | max similarity | ≥0.90 | top match same class | best cross-class |
|---|---|---|---|---|
| 32px | 0.990 | 66 | 50% | 0.984 |
| 64px | 0.987 | 58 | 48% | 0.980 |
| 128px | 0.986 | 48 | 44% | 0.977 |
| 128px high-pass | 0.848 | 0 | 50% | 0.545 |

**Reading this table.** On raw pixels the similarities look alarming — 48 test
images have a training match above 0.90 at 128px. But the *best cross-class*
match is almost as high as the best same-class match, which is the signature of a
shared nuisance variable rather than duplicated content. Removing low-frequency
illumination settles it: no test image has any training match at or above 0.90,
and the best cross-class match falls to 0.545. **There is no near-duplicate
leakage**; the raw-pixel similarity is an illumination artefact.

## 3. Architecture

This section describes **what was built and why each piece was expected to help**.
Read it as a set of hypotheses: §6.3 tests every component against the bare
EfficientNet-B0 backbone, and most of them do not survive. The architecture is
documented in full regardless, because the negative result is only meaningful if
the thing that failed is specified precisely.

The network is split at an explicit encryption boundary.

```
CLIENT (plaintext, holds secret key)
  image (B,1,160,160)
    ├─ EfficientNet-B0 ─────────────► g (B,1280) → Linear+LN → (B,256)
    └─ Multi-scale CNN → (B,128,10,10)
         └─ Sobel-gated chunk attention → (B,128) → Linear+LN → (B,256)
  gated fusion: z·g + (1−z)·l           → (B,256)
  compression:  Linear 256→64, tanh     → v (B,64), bounded [−1,1]
  CKKS encrypt                          → Enc(v)
SERVER (ciphertext only, no secret key)
  Enc(v) → mm(W₁)+b₁ → square → mm(W₂)+b₂ → Enc(logits) (B,6)
CLIENT
  decrypt → softmax → predicted class
```

| component | parameters |
|---|---|
| global branch | 4,335,420 |
| local branch | 190,816 |
| chunk attention | 8,322 |
| fusion | 197,120 |
| compression | 16,448 |
| encrypted head | 2,278 |
| total | 4,750,404 |
| trainable | 4,750,404 |

The encrypted head is only 2,278 parameters — three orders of
magnitude smaller than the feature extractor. That asymmetry is what makes
homomorphic evaluation affordable at all.

### 3.1 Mathematical formulation

**Multi-scale block.** For input `x ∈ ℝ^(C×H×W)`, four parallel paths with
receptive fields {1, 3, 5, 5} each emit `C_out/4` channels:

```
y = BN(W_f · concat[P₁(x), P₃(x), P₃,d=2(x), P₅(x)]) + shortcut(x)
```

**Sobel-gated chunk attention.** The feature map is pooled to a `g×g` grid giving
chunk tokens `fᵢ ∈ ℝ^C`. Per-chunk Sobel energy `eᵢ` is standardised across chunks
to `êᵢ`. Scores and weights:

```
aᵢ = MLP(fᵢ) + λ · êᵢ          λ ∈ ℝ, learnable
w  = softmax(a / T)
descriptor = Σᵢ wᵢ · fᵢ
```

`λ` is a single scalar expressing how much the network trusts the gradient prior.
It is initialised at 1.0 and reported as a measured outcome.

**Measured value: λ = 0.9924.**

**Gated fusion.** With global `g` and local `l` both in `ℝ^256`:

```
z     = σ(W₂ · ReLU(W₁ · [g ; l] + b₁) + b₂)     z ∈ (0,1)^256
fused = z ⊙ g + (1 − z) ⊙ l
```

The gate is a *vector*, not a scalar: the model can source some feature dimensions
from the global branch and others from the local branch for the same image.

**Encrypted head.** `logits = W₂ · (W₁v + b₁)² + b₂`, multiplicative depth 3.

## 4. Baseline reproduction

Reproduced from the published description. The paper's prose is internally
inconsistent in places; every assumption we were forced to make is listed.

**Stated explicitly by the paper:** 112×112 resize, grayscale, global histogram
equalisation; rotation ±15°, horizontal flip, translation ±10%; a 7×7 convolution
then FC 256→128 and FC 128→6; ReLU in plaintext and a square activation under
encryption; Adam with cross-entropy; 28×28 chunks over a 4×4 grid (Table 2).

**Not stated — our documented assumptions:**

| unspecified | our choice | rationale |
|---|---|---|
| convolution channels | 32 | never given; 32 lets the pooled map reach the stated 256-unit FC input |
| route to 256 FC units | adaptive average pool to 32×2×4 | no stated arithmetic produces 256 from a 7×7 conv over 112×112 |
| conv stride / padding | stride 1, padding 3 | 'same' convolution, the standard reading |
| chunk size conflict | 28×28 | 28×26 appears twice but contradicts both the chunk count and the image size |
| split sizes | this project's common split | none reported; required for a like-for-like comparison |
| epochs / LR / batch | 60 epochs, 1e-3, 32 | none reported |

### 4.1 Is the failed reproduction our assumption's fault?

We report that the published 97.1% does not reproduce. That claim leans on
choices the paper forced on us — above all the convolution width, which it never
states. If a different width recovered 97.1%, the honest conclusion would be
"the paper under-specifies its architecture", not "the result does not
reproduce". So the assumption is tested rather than defended:

| baseline variant (seed 42, full data) | accuracy | macro F1 |
|---|---|---|
| 32 channels, square **(our reproduction)** | 94.72% | 94.73% |
| 128 channels, square | 86.67% | 86.67% |
| 16 channels, square | 95.00% | 95.03% |
| 64 channels, square | 90.28% | 90.15% |
| 32 channels, ReLU | 86.94% | 86.89% |

No setting reaches the published 97.1% (best:
95.00%). The gap is therefore not explained by our
convolution-width or activation assumptions, which strengthens rather than
weakens the reproduction finding. It remains possible that some other
unreported detail — the split, the schedule, the augmentation ordering —
accounts for it; we cannot test what is not described.

**A side finding worth recording.** The paper uses ReLU in its plaintext
model and the square activation under encryption, and its Table 3 row
for NEU-CLS is the square one. Swapping our reproduction to ReLU costs
7.78 points (86.94% against 94.72%). The square
activation is not merely the CKKS-compatible choice here — on this
architecture it is also the better-performing one, which is the opposite
of the usual trade-off where a polynomial activation is accepted as a
cost of encryption. With 35 k parameters and 1 223 training images the
comparison is small enough that we report it as an observation rather
than a general claim.

**Documented problems in the base paper** (detailed in `reports/literature_review.md`):
its headline Table 3 compares accuracy across four different datasets; no precision,
recall or F1 is reported for NEU-CLS; CKKS is expanded incorrectly in one section;
and encryption is reported to *improve* accuracy, which an approximate scheme cannot do.

**What this comparison does and does not isolate.** The two models differ in more
than architecture: SAGE-HE uses an ImageNet-pretrained backbone with ~4.7 M
parameters, while the reproduced baseline is a ~35 k-parameter network trained from
scratch, because that is what the base paper describes. A large part of the gap is

the architectural contribution would be misleading.

The contribution is isolated instead in the ablation (§6), where every stage from 2
onwards shares the same pretrained backbone and the same training protocol, so the
only thing that varies is the component under test. Stage 2 (EfficientNet-B0 alone)
is the correct reference point for judging whether the local branch, the chunk
attention and the gated fusion earn their place; stage 1 is the correct reference
point for judging the system as a whole against prior work.

### 5.2 Is the difference statistically real?

Both models are scored on the **same 360 test images**, so their predictions are
paired and the appropriate test is McNemar's, not a two-sample proportion test.
McNemar's looks only at the *discordant* images — those one model classifies
correctly and the other does not — and asks whether the split between the two
kinds of disagreement is more lopsided than a fair coin.

| outcome on a test image | count |
|---|---|
| both correct | 341 |
| SAGE-HE correct, baseline wrong | 19 |
| baseline correct, SAGE-HE wrong | 0 |
| both wrong | 0 |
| discordant pairs | 19 |

| quantity | value |
|---|---|
| accuracy, baseline | 94.72% |
| accuracy, SAGE-HE | 100.00% |
| accuracy difference | +5.28 points |
| 95% bootstrap CI on the difference | [+3.06, +7.78] points |
| test | exact binomial |
| p-value | 3.815e-06 |
| significant at α = 0.05 | yes |

All **19** disagreements fall the same way: SAGE-HE never
misclassified an image that the reproduced baseline got right. That is the
strongest shape this test can take, and it is why the exact binomial p-value is
3.8e-06 despite the modest test-set size. The bootstrap interval
resamples *images*, keeping each image's pair of predictions together, so it
respects the same pairing.

The caveat from the previous section still applies in full: this establishes that
the two **systems** differ, not that the chunk-selection or fusion mechanisms are
responsible. The backbone difference is confounded with the architecture here;
§6 is where the components are isolated.

### 5.3 What the learned chunk attention actually does

A selection mechanism that fires uniformly is doing nothing. Concentration below
is `1 − normalised entropy` of the 16 attention weights: 1.0 means all mass on a
single chunk, 0.0 means perfectly uniform.

| class | max weight | concentration |
|---|---|---|
| crazing | 0.252 | 0.148 |
| inclusion | 0.643 | 0.423 |
| patches | 0.160 | 0.122 |
| pitted_surface | 0.147 | 0.037 |
| rolled-in_scale | 0.223 | 0.122 |
| scratches | 0.260 | 0.160 |

The pattern matches the physics of the defects. `inclusion` — a few dark
streaks in one region — draws the most concentrated attention (0.42),
while `pitted_surface` — pitting spread across the whole surface — is close to
uniform (0.04). The mechanism is responding to defect
locality rather than firing arbitrarily.

## 6. Ablation

### 6.1 Why the ablation is run at reduced data

On the full training split, SAGE-HE reaches 100% test accuracy and validation
macro-F1 saturates at 1.0 within two epochs. Every architectural variant is then
at ceiling, and an ablation would be ranking noise while presenting it as evidence.
The ablation is therefore run on a stratified 15% subset of the training split
(~30 images per class), where the objective retains dynamic range. Validation and
test splits are never subsampled.

### 6.3 Negative results: the proposed components do not help

This is the central finding of the ablation, and it goes against the proposed
architecture. It is reported in full.

| contrast | mean Δ macro F1 (pts) | median Δ | per-seed Δ | same sign on every seed? |
|---|---|---|---|---|
| adding the local branch (stage 6 − stage 2) | -2.82 | -1.45 | -1.1, -5.9, -1.5 | yes |
| adding chunk attention (stage 7 − stage 6) | -1.26 | -1.07 | -3.6, -1.1, +0.9 | no |
| adding the Sobel prior (stage 7 − stage 8) | +21.55 (collapsed seed [1337]; excluding it -1.28) | +1.21 | -3.8, +67.2, +1.2 | no |
| full model vs its own backbone (stage 7 − stage 2) | -4.08 | -4.72 | -4.7, -7.0, -0.6 | yes |

The per-seed column matters more than the mean here. Seed-to-seed spread at 61
training images is several points, so a mean on its own is weak evidence. What
makes the headline contrast credible is not its magnitude but its
**consistency of sign**: the full model scores below its own backbone on every
seed, by between 0.6 and 7.0 points. The design studies in §6.5 do not have
that property, and are reported there as indistinguishable rather than ranked.

The 5% result could in principle be an artefact of the very-low-data regime,
where a from-scratch branch has no chance to learn. A targeted study runs the
backbone alone against the full model at larger fractions, with matched seeds:

| training fraction | backbone alone | full SAGE-HE | Δ (pts) | seeds |
|---|---|---|---|---|
| 10% | 98.81% | 99.35% | +0.55 | 3 |

**Verdict.** The full SAGE-HE architecture never *materially* outperforms its own EfficientNet-B0 backbone at any training-set size measured. It is materially worse at 5% (-4.08 pts); at 10% (+0.55 pts) the gap falls inside the seed-to-seed spread and changes sign across seeds, because both arms are approaching the dataset's ceiling. The proposed components are therefore clearly harmful when labelled data is scarce, and indistinguishable from the bare backbone once it is not. No measured regime shows a reliable benefit.

**Why, mechanically.** Four things combine:

1. **The local branch has no pretraining.** On 61 images it cannot learn useful
   filters — trained alone it scores anywhere from 11% to 72% macro F1 depending
   on seed. Fusing a near-random branch into a strong pretrained one adds variance
   and costs accuracy, which is exactly what stages 4–6 show.
2. **The gate mitigates but does not rescue.** Gated fusion recovers some of what
   plain concatenation loses, which is weak evidence that the gate does what it
   was designed to do — learn to discount an unhelpful branch — but discounting a
   harmful input is not the same as benefiting from it.
3. **The Sobel prior is photometric, not semantic** — it scores a lighting seam or
   a mill-roll edge exactly as highly as a defect. That is the mechanism we
   expected to hurt, and the point estimate does go that way once the collapsed
   seed is excluded. But the per-seed signs disagree, so **this particular
   contrast is not established**: we can say the prior is not demonstrably
   helping, not that it is demonstrably harming. The same caveat applies to the
   chunk-attention contrast in isolation.
4. **λ could not adapt.** See §6.4.

**What is and is not established.** Two contrasts hold on every seed and carry the
conclusion: adding the local branch costs accuracy, and the full model scores
below its own backbone. The finer-grained attributions — exactly how much of that
is the chunk attention versus the Sobel prior — do not separate cleanly at three
seeds and 61 training images, and are not claimed. The headline stands on the
sign-consistent contrasts alone.

**What survives.** The negative result is about the *architectural* additions. It
does not touch the parts of this project that do hold up: the reproduction and
audit of the base paper (§4), the encrypted inference and its exactness bound
(§7), the dataset integrity audit (§2), and the evaluation methodology that made
this finding visible at all (§6.1). A saturated benchmark plus a single-seed
full-data comparison would have shown 100% for every variant and concluded,
wrongly, that the components were fine.

**What this implies for the system.** The configuration actually supported by the
evidence is EfficientNet-B0 plus the compression layer and the CKKS polynomial
head — the privacy architecture without the extra feature machinery. That is a
simpler system than the one proposed, and it is the one a follow-up should build.

### 6.4 λ did not learn, and why that matters

The design intent was that λ — the learnable scalar weighting the Sobel prior
inside the chunk score — would act as a readout: drive it toward zero and the
model is telling us the prior is useless. It does not work.

| quantity | value |
|---|---|
| initialised at | 1.0 |
| mean λ across all trained runs | 0.9971 |
| range | 0.9903 – 1.0051 |
| maximum drift from initialisation | 0.0097 |

λ moves by less than 0.01 in every run. A single unregularised scalar among
4.7 million parameters receives negligible gradient pressure, especially once
the loss is near zero. As a sanity check, the no-Sobel control — where λ
receives no gradient at all — sits at exactly 1.0000, confirming that λ does
get *some* gradient when used, just far too little to be informative.

So the claim that λ measures the prior's worth is withdrawn. The
with/without-Sobel ablation control is the experiment that actually answers
the question, and it answers it negatively. A design that wanted λ to be
informative would need to regularise it toward zero and report the
regularisation strength, or parameterise it per-chunk rather than as one scalar.

| res 200 | 91.77 ± 2.02 | +2.40 | better |  |
| topk 4 | 43.02 ± 41.90 | -46.36 | worse | 2 collapsed |

Read `topk 4` with care: the gap there is driven by
runs that failed to train rather than by a consistent effect, so it says
the setting is **unstable at this data size**, not that it is uniformly
worse. The one clean effect in this table is the input resolution.

The defensible conclusion is therefore narrower than the raw ranking suggests:
the specified configuration is **not demonstrably better than the alternatives,
and not demonstrably worse either** — except where the gap clears the noise
(notably 32-d compression, which is clearly harmful). That is a weaker claim
than "our design choices were wrong", and it is the one the data supports.

These are measured at 61 training images, so they describe the low-data regime
specifically. At full training size every variant is at ceiling and the studies
would show nothing — which is the same reason the ablation is run here. The
defaults are deliberately left unchanged in the code so that every number already
reported remains reproducible; the finding is reported rather than quietly fixed.

## 7. Encrypted inference

### 7.1 Threat model

Two parties, honest-but-curious server.

* **Client** holds the image and the secret key, runs the whole feature extractor in
  plaintext, and encrypts only the 64-dimensional compressed vector.
* **Server** holds the classifier weights and a *public-only* context (encryption,
  Galois and relinearisation keys). It evaluates the polynomial head on ciphertext.

A note on scope, given §6.3: the encrypted-inference result does **not** depend on
which feature extractor sits in front of it. The encrypted head is the same
64 -> 32 -> 6 polynomial whether the client runs the full proposed architecture or
the bare EfficientNet-B0 backbone, so the correctness, security and latency
findings below stand independently of the negative architectural result. They are
measured here on the full model because that is the system the project proposed.

**Protected:** the feature vector in transit and at the server, and the prediction.
The server can decrypt neither — `tests/test_encryption.py` asserts that the server
context raises on a decryption attempt and that it reports as public-only.

**Not protected, stated plainly:**

1. This is **not** the base paper's setting. Jia et al. encrypt image chunks, so their
   client does almost no work. Here the client runs the entire extractor and must be
   trusted with its weights. Ours protects the *server* side of the boundary only;
   theirs targets the image itself. These are different trade-offs, not a ranking.
2. CKKS is **not circuit-private**: an adaptively-chosen input could leak information
   about the server's weights. Noise flooding is not implemented.
3. The compressed vector is a lossy but real function of the image. We make no formal
   claim that it hides the image's content from a party that holds it in the clear.

### 7.2 Parameters and security

| parameter | value |
|---|---|
| scheme | CKKS |
| polynomial modulus degree | 16384 |
| coefficient modulus chain | (60, 40, 40, 40, 60) |
| total modulus bits | 240 |
| global scale | 2^40 |
| multiplicative depth available | 3 |
| multiplicative depth required | 3 |

**Security.** n=16384, 240 modulus bits (<= 438 permitted at 128-bit security): meets 128-bit classical security. For polynomial modulus degree 16384 the
HomomorphicEncryption.org standard permits up to 438 coefficient-modulus bits at
128-bit classical security; using fewer bits at a fixed degree *increases* the
margin. The depth accounting is verified empirically: a fourth multiplication
exhausts the chain and raises, which `tests/test_encryption.py` asserts.

### 7.3 Correctness under encryption

| quantity | value |
|---|---|
| test images evaluated | 360 |
| encrypted vs plaintext agreement | 100.00% |
| prediction flips | 0 |
| plaintext accuracy | 100.00% |
| encrypted accuracy | 100.00% |
| max absolute logit error | 1.430e-02 |
| mean absolute logit error | 2.766e-03 |
| minimum decision margin | 3.6129 |
| mean decision margin | 4.7409 |
| error / (margin / 2) | 0.00791 |

The polynomial head is *trained* with the square activation it is *evaluated*
with, so the plaintext and encrypted models are the same function up to CKKS
approximation error.

**Why that error cannot move a prediction.** Agreement on a particular test set
is an observation; the margin analysis turns it into a bound. The *decision
margin* is the plaintext gap between the top-1 and top-2 logits, and a prediction
can only flip if the CKKS perturbation exceeds half that gap. On the tightest
decision in the test set the maximum observed error consumes only
**0.79%** of that budget — the error would have to
be roughly **126×** larger before any prediction
could change. The agreement result is therefore robust, not a coincidence of
this particular sample.

This is also the expected direction of the effect, and it is worth contrasting
with the base paper, which reports encryption *improving* classification accuracy.
An approximate scheme adds numerical error; it cannot add information.

### 7.5 Compression trade-off

| compressed dim | macro F1 | HE evaluation | ciphertext | agreement |
|---|---|---|---|---|
| 32 | 56.88% | 808 ms | 836 KB | 100.0% |
| 64 | 89.38% | 1418 ms | 835 KB | 100.0% |
| 128 | 91.13% | 2864 ms | 836 KB | 100.0% |
| 256 | 90.66% | 5578 ms | 835 KB | 100.0% |

Accuracy here is measured in the reduced-data regime for every width, including
the default 64 (whose same-regime run is ablation stage 7). Mixing a full-data
number into this column would put a 100% entry beside 61-image entries and make
the curve meaningless.

**This is the one design decision the evidence settles cleanly.** Latency
roughly doubles with each step in width, while accuracy above 64 does not
move outside the seed-to-seed spread: 89.38% at d=64
against 91.13% at d=128, for
2.0x the homomorphic evaluation time.
Below 64 the model breaks down (56.88% at d=32). So 64 is
the knee of the curve, and it is chosen on the measurement rather than assumed.

Note also that ciphertext size is flat across widths: at this polynomial
modulus a ciphertext carries 8192 slots regardless of how few are used, so
compression buys evaluation time, not bandwidth. Any bandwidth saving would
have to come from packing several images into one ciphertext.

## 9. Explainability

Grad-CAM over the backbone's final convolutional features, alongside the model's own
chunk-attention weights. Two caveats are stated rather than glossed:

1. Grad-CAM here explains the **client-side extractor**, not the encrypted head. The
   head sees a 64-dimensional vector with no spatial structure left, so there is
   nothing spatial to attribute.
2. SAGE-HE's logits pass through a **squared** activation, so the gradient of a logit
   with respect to a feature is not sign-stable in the way it is after a ReLU stack —
   a feature can raise a logit by being strongly negative.

An attractive heatmap is not evidence of correctness, and is not presented as such.

Misclassified test images: **0** of 360, so there is no failure set to show for
this model. Rather than omit the analysis, `results/gradcam/gradcam_hard_cases.png`
shows the 19 images the reproduced baseline got wrong
with this model's attribution on them — the genuinely hard cases. Those errors
concentrate in faint `inclusion` streaks the baseline reads as `pitted_surface`,
which is the same pair its per-class F1 singles out.

## 10. Limitations

1. **The benchmark is saturated.** NEU-CLS cannot separate strong modern
   architectures at full training size. Every component conclusion in §6 comes from
   the reduced-data regime and should not be extrapolated to the full-data setting.
2. **The test set is small.** 360 images; a single image is 0.28 accuracy points.
   Wilson score intervals are reported for this reason.
3. **No GPU.** All training and all latencies are CPU measurements on 4 vCPU and are
   not comparable to GPU figures elsewhere. The project brief specified GPU training;
   none was available in this environment.
4. **The privacy model is weaker than the base paper's goal.** See §7.1.
5. **The baseline is a reconstruction**, not the authors' code. Six documented
   assumptions were required (§4).
6. **The proposed architectural contribution is not supported by the evidence.** The
   plaintext-features/encrypted-head split was already prior art (PRISM, 2025), and
   the learned Sobel-conditioned chunk selection — the one genuinely new piece —
   measurably hurts on NEU-CLS (§6.3). What remains defensible is the reproduction
   and audit of the base paper, the exactness bound on encrypted inference, and the
   saturation-aware evaluation protocol. We do not claim an architectural advance.
7. **λ is not the instrument it was designed to be** (§6.4); any future version needs
   it regularised or parameterised per chunk.
7. **Single dataset.** No cross-dataset validation; the λ finding in particular should
   be checked where gradient priors are less reliable.
